# Research, editorial gate і review-ready випуск

Для monthly застосувати references/cadence.md: синтезувати зміни за календарний місяць, а не склеювати тижневі огляди; YYYY-Www у назвах замінити на YYYY-MM. Кількість тез і тривалість не збільшувати автоматично.

Зміст: [докази](#1-зібрати-доказовий-пакет), [оцінювання](#2-застосувати-оцінювання-до-сценарію), [research gate](#3-research_gatemd), [review](#4-yyyy-www_reviewmd), [ledger](#5-ledger-без-штучних-завдань), [QA](#6-редакторська-перевірка).

## 1. Зібрати доказовий пакет

Почати з живих питань слухача та огляду релізів у його темах. Для короткого пілоту достатньо 5–8 кандидатів; для довгого випуску орієнтир 10–15. Це не квота. Відкривати й читати джерело, не покладатися лише на пошуковий snippet або заголовок.

Для кожного кандидата створити evidence card:

| Поле | Що записати |
|---|---|
| Claim / thesis | Перевірюване твердження, не рекламний слоган |
| Why this listener | Конкретне питання, рішення або навчальна потреба |
| Publication date | Коли матеріал опубліковано; unknown, якщо не встановлено |
| Event / data date | Коли сталася подія або до якого періоду належать дані |
| Effective date | Коли правило починає діяти, якщо доречно |
| Retrieved / cutoff | Коли перевірено, яку часову межу використовуємо |
| Source | Автор/організація, заголовок, прямий URL, primary/secondary |
| Evidence | Що джерело безпосередньо підтверджує, з місцем у документі |
| Limits / incentives | Вибірка, метод, denominator, конфлікти інтересів |
| Mechanism | Причина → передавання ефекту → значення для питання |
| Counter / falsifier | Незалежне свідчення або спостереження, що спростує механізм |
| Confidence | High / medium / low з причиною |
| Delta | Що нового відносно минулих випусків; не тільки нова дата |

Розрізняти announcement, consultation, enacted rule, implementation та observed outcome. Для науки відділяти preprint, peer review, replication і causal evidence. Для культурного аналізу відділяти історичний факт, атрибуцію й інтерпретацію.

Primary first не означає primary always right. Офіційна заява доводить, що організація це заявила, але не обов'язково істинність оцінки. Перевіряти незалежність джерел за походженням, не за кількістю сайтів. Для авторитетного вузького факту одна першопублікація може бути достатньою; широка consequential thesis потребує перевірки контексту й альтернативних пояснень.

Для історичного cutoff не використовувати пізніші факти як тодішні знання. Якщо сторінка змінена і попередня версія недоступна, прямо вказати неможливість перевірки станом на задану дату. Майбутню дату відділяти як план/очікування.

## 2. Застосувати оцінювання до сценарію

| Критерій | Макс. | Питання |
|---|---:|---|
| Релевантність слухачу | 25 | Чи змінює рішення, модель, важливе питання або розуміння обраної теми? |
| Значущість | 15 | Чи важливий зміст без гучного імені, бренду або хайпу? |
| Якість доказів | 20 | Чи прозорі джерела, метод, дати, походження й обмеження? |
| Ясність механізму | 10 | Чи зрозуміло, чому це має значення? |
| Довговічність | 10 | Чи корисна ідея після цього тижня? |
| Контрперевірка | 10 | Чи є реальна межа застосовності/альтернатива/falsifier? |
| Новизна для серії | 5 | Чи є delta, а не повтор старого висновку? |
| Придатність для аудіо | 5 | Чи зрозуміло без екрана? |

Показувати компоненти й коротку причину, а не лише суму. Бали — редакційна евристика, не вимір істини.

- 85–100: кандидат на major thesis.
- 75–84: підтримка або короткий додатковий сегмент; не прихована четверта major thesis.
- 65–74: show notes/watchlist.
- Нижче 65: відсіяти.

Застосувати caps і hard gates до відбору:

- Немає доступного primary record, де він очікується: cap 69; виняток не вигадувати.
- Consequential thesis з одного походження без незалежної перевірки: cap 74.
- Повтор висновку з останніх чотирьох випусків без справжнього delta: мінус 15 після caps.
- Нерозкритий матеріальний conflict of interest, порушення приватності, вигадане посилання: reject.
- Медична/правова/податкова/фінансова рекомендація без актуального авторитетного підтвердження й потрібного контексту: reject або переформулювати в обмежене питання до фахівця.
- Формальна суперечка не потрібна там, де є сильний консенсус: перевірити boundary condition, не створювати false balance.

Для кожної major thesis перевірити: relevance, materiality, durability, adequate evidence, clear mechanism, credible counter-test. Потрібні щонайменше п'ять «так» із шести; evidence і privacy gates обов'язкові незалежно від суми.

## 3. Research_Gate.md

Записати metadata і часові межі; короткий огляд пошуку; таблицю кандидатів із рішенням include/support/monitor/reject; evidence cards для обраного; governing question; максимум три тези; контраргументи; невирішені прогалини; план хронометражу; статус погодження.

Якщо жодна теза не проходить, не оголошувати «насичений тиждень». Запропонувати короткий update, evidence-backed evergreen або no episode. Передбачувана довжина не виправдовує слабку перевірку.

## 4. YYYY-Www_Review.md

Створити один автономний review-документ:

1. Metadata: серія, ID, revision, coverage, cutoff/timezone, статус; estimated або measured runtime.
2. Executive Signal: один абзац із головним питанням і зміною розуміння.
3. Назва, governing question, одна–три тези.
4. Evidence map: confirmed fact / editorial inference / hypothesis to verify. Посилання біля фактів.
5. Повний spoken script із chapter timestamps; до рендера позначити їх approximate. Для кожної тези дати signal → mechanism → counter-view → model update → decision state; transitions пояснюють зв'язок, не просто оголошують рубрику.
6. Source-linked show notes: primary/secondary, назва, publication/event dates, що саме підтримує джерело, caveat.
7. Decision & Learning Ledger.
8. What we intentionally ignored: що відсіяли і чому, без довгого каталогу шуму.
9. QA: бали/обмеження, citation audit, continuity, narration status і відкриті blockers.

Матеріальне твердження — число, дата, причинний/емпіричний висновок, чинність правила, порівняння або факт, від якого залежить теза. Дати прямий URL поруч, за потреби section/page. Inference теж показує джерельні premises, але не видає джерело за автора редакційного висновку. Не цитувати самих агентів.

Гіпотетичний приклад явно назвати вигаданим. Не придумувати цитати, інтерв'ю, досвід слухача або результати досліджень. Перекладати природно, зберігати точний зміст і потрібні canonical terms.

## 5. Ledger без штучних завдань

Для кожного consequential output вибрати рівно одну категорію:

| Категорія | Коли |
|---|---|
| ACT NOW | Є достатні докази, застосовність і низька невизначеність наступного кроку |
| ASK AN EXPERT | Потрібна кваліфікована оцінка особистої/юрисдикційної ситуації |
| DELEGATE RESEARCH | Важливе конкретне питання ще можна дослідити; це пропозиція, не виконана делегація |
| MONITOR | Є визначений майбутній сигнал, але зараз дії не виправдані |
| IGNORE | Свідомо не витрачати увагу або нічого не змінювати |

Поля: output; category; reason; suggested owner; next trigger. Якщо людина нікого не призначила, owner = «слухач/редактор, запропоновано», не вигадане ім'я. Trigger може бути «немає; свідомий no action». Рекомендація ACT NOW не дає дозволу виконати дію.

У навчальному режимі вести окремі model updates і питання для роздумів без нав'язаних action categories. Категоризувати лише consequential outputs; не потрібно п'ять рядків заради всіх п'яти категорій.

## 6. Редакторська перевірка

Перевірити кожне матеріальне твердження проти відкритого джерела. Перерахувати важливі числа; відділити nominal/real, level/change, percentage/percentage points, sample/population. Перевірити причинність, альтернативні пояснення та чесність впевненості.

Зробити незалежний критичний прохід: прибрати перебільшення, повтори, рекламні оцінки, компліменти слухачеві й зайву термінологію. Для довжини додавати лише потрібні механізми, сильні приклади, обмеження й короткі recaps — не filler. Перевірити, що висновок не сильніший за докази.
