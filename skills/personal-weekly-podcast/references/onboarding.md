# Onboarding і робочий стан

## Коротке інтерв'ю

Не показувати довгу анкету відразу. Дозволити відповісти голосом, одним абзацом або «обери defaults». Не питати вже надане.

Перша хвиля — максимум три запитання в одному повідомленні:

1. Для чого цей час: краще ухвалювати рішення, глибше розуміти світ, відпочивати з цікавими ідеями чи поєднання? Які три–п'ять тем цікавлять зараз?
2. Що вже добре знаєш, у чому хочеш розібратися і що точно не хочеш чути? Можна навести приклад хорошого й невдалого матеріалу.
3. Якою мовою, приблизно скільки хвилин і як часто — щотижня чи щомісяця — хочеш слухати? Де зазвичай слухатимеш — прогулянка, дорога, вдома?

Друга хвиля — після відповідей, тільки потрібні уточнення:

1. Які питання або рішення важливі на найближчі місяці? Які країни чи перспективи потрібні для контексту? Це необов'язково: не вимагати професійної або фінансової інформації.
2. Більше подій обраного періоду чи глибоких історій і пояснень? Спокійний один голос чи інший формат? Який баланс незнайомих і вже знайомих тем?
3. Які матеріали можна використовувати, а що має залишитися приватним? Чи достатньо відкритих джерел? Чи є бажаний інструмент озвучення? Якщо ні — перевірити доступні можливості самостійно.

Не перетворювати невідповіді на згоду. Показати пропонований формат і тільки матеріальні unresolved choices. Запит «без уточнень» означає роботу з позначеними defaults, а не вигаданий профіль.

## Пропоновані, не канонічні defaults

- Мета: змішане навчання й корисне розуміння, без обов'язкових особистих дій.
- Частота: weekly як provisional default, якщо користувач ще не обрав; monthly — рівноцінний варіант. Частота не створює автоматичного розкладу.
- Пілот: 25–30 хвилин; запропонувати 45–60 хвилин для більшої глибини. Не зменшувати явно запитану тривалість без пояснення.
- Мова: мова розмови, з перевіркою перед озвученням.
- Один спокійний голос; природна мова; короткі пояснення термінів; без інсценованих «експертів» і бантеру.
- Одна–дві тези в короткому пілоті, максимум три в довгому.
- Current/evergreen: 60/40 як гнучкий орієнтир, не квота.
- Відкриті джерела; приватне використання; без платних витрат, публікації та автоматичного розкладу.
- Перший review gate — до довгого сценарію; надалі можна погодити end-to-end режим.
- Якщо timezone невідомий, технічний cutoff в UTC — робоче припущення, не місце проживання.

## 00_Listener_Profile.md

Зберегти версію, дату, власника та статус підтвердження. Заповнити:

| Поле | Зміст |
|---|---|
| Навіщо слухати | Рішення, навчання, цікавість або їх баланс |
| Бажаний результат | Що людина хоче розуміти після випуску |
| Пріоритети | P1 основні питання; P2 розширення; P3 необов'язкова цікавість, без чужих тематичних квот |
| Рівень | Окремо для кожної головної теми |
| Живі питання | Необов'язкові питання й горизонт актуальності |
| Не включати | Теми, формати, приватні дані, небажані повтори |
| Контекст | Тільки добровільно наданий і потрібний для редакційних рішень |
| Статус | Confirmed preference / provisional default / hypothesis to confirm |

Не зберігати credentials. Згадка «як у подруги» означає схожий процес, не автоматично її профіль.

## 01_Source_Map.md

Побудувати карту під обрані теми після onboarding. Перевірити існування й доступність джерел, не вигадувати назви та URL. Почати з кількох сильних джерел на основну тему; розширювати за прогалинами.

Для кожного: тема/питання; назва й URL; primary/secondary; для чого придатне; чого не доводить; частота оновлень; доступ/paywall; стимули й bias; незалежне counter-source; дата повторної перевірки.

Адаптувати типи доказів:

- Наука: оригінальне дослідження, дані, методи; для стану знань — систематичні огляди й consensus documents.
- Культура/історія: твори, архіви, музейні каталоги, критичні видання; наукова інтерпретація не дорівнює архівному факту.
- Технології: документація, технічні звіти, відтворювані оцінки, filings; заяву виробника відділяти від незалежної перевірки.
- Право/економіка: чинний акт, регулятор, офіційний dataset; перевіряти юрисдикцію і часову застосовність.

Позначити knowledge gaps, discovery-only джерела й правила відсіву. Кілька передруків одного релізу рахувати одним походженням.

## 02_Format_and_Voice.md

Зафіксувати назву серії (тимчасова допустима), мову, хвилини, кількість тез, глибину термінів, голос, темп, current/evergreen mix, approval mode, структуру та доступний audio backend.

Додати cadence (weekly/monthly), coverage convention, timezone, бажаний момент випуску й cutoff. Дотримуватися references/cadence.md; частоту й хвилини погоджувати незалежно.

Модульна структура: головне питання → одна–три історії з доказами й запереченням → що змінилося в розумінні → питання/рішення/свідомий no action. Не робити рубрику обов'язковою без сигналу.

Зберегти pronunciation glossary для повторюваних імен та абревіатур. Після пілоту уточнити реальний темп; не канонізувати word-count як тривалість.

Після погодженої проби зберегти audio preset: маршрут (прямий/через сайт), сервіс, назву голосу й ID якщо доступний, модель, мову, налаштування швидкості, дату погодження, виміряний темп і версію словника. Невідомі значення позначити unknown. Не вимагати voice ID від нетехнічного користувача; достатньо назви або скриншота без приватних даних. Не запускати нове налаштування щотижня, якщо нічого не змінилося.

## Podcast_State.md

Зберігати мінімальний стан для іншої сесії:

- Ідентифікатор серії та посилання на три канони з версіями.
- Останній підтверджений профіль і непідтверджені defaults.
- Cadence, поточний episode ID, coverage window, cutoff з timezone, approval mode; зміни частоти та межі переходу.
- Стадія, завершені файли з реальними посиланнями, blockers, наступний крок.
- Останні чотири випуски: дата, тези, model updates, відкриті тригери; старі тримати в архіві, не видаляти.
- Виправлення фактів і стан їх перенесення до Narration Master/аудіо.
- Scheduler: not configured або реальний ID/час/режим після підтвердженого створення.
- Audio preset, погоджений бюджет і дозволена передача тексту; статус проби голосу, посилання на аудіопакет, виконаний QA й невиконані перевірки, не секрети доступу.

Стан не є доказом актуальних зовнішніх фактів. Не позначати published те, що лише scripted. Для виправлення зберігати revision, не змінювати виданий файл непомітно.
